# Phase 0 Deliverable — Asset Compatibility Audit

Rule 22 permits legally licensed general-purpose assets and templates **after** a compatibility audit.
Rule 1 requires that Project Uppercut's finished identities, mechanics, tuning, writing, branding,
presentation and project-specific code remain original. No asset enters the project without a
completed audit committed alongside it.

## Audit checklist — every item must be answered

| # | Item | Answer | Evidence |
|---|---|---|---|
| 1 | Commercial license permits this use | | |
| 2 | Modification rights | | |
| 3 | Skeleton compatibility | | |
| 4 | Retargeting behaviour | | |
| 5 | Root motion behaviour | | |
| 6 | Performance cost | | |
| 7 | Network suitability | | |
| 8 | Visual consistency with project direction | | |
| 9 | Engine version support | | |
| 10 | Maintainability and update path | | |

## Originality gate — additional to the Rule 22 list

| # | Item | Answer |
|---|---|---|
| 11 | Does the asset carry a recognisable likeness, name, or branding from an existing property? | must be **no** |
| 12 | Would a reasonable observer identify the source game or character from it? | must be **no** |
| 13 | Is any bundled audio, announcer line or UI motif protected material? | must be **no** |

An asset that passes 1–10 but fails 11–13 is rejected regardless of license.

## Outcome

**Accepted / Accepted with modification / Rejected** — with the reason recorded. Audits live beside the
asset and are cited in the commit that introduces it, so the record is greppable later.
