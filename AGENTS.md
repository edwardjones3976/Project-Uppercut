## Cursor Cloud specific instructions

Project Uppercut is a game project. Only its **Python toolchain** runs in a Linux
cloud environment; the Unreal Engine 5.8.1 sandbox (`sandbox/`) and the PowerShell
runners in `tools/engine/` are **Windows-only** and cannot be built or run there.

There are **no long-running services, servers, ports, or databases** — all state is
file-based JSON under `data/`, `schemas/`, and `fixtures/`. "Running the app" means
running the validators and the deterministic reference bout simulator.

### Standard commands (see `CONTRIBUTING.md` and `.github/workflows/validate.yml`)

- Tests: `python3 -m pytest -q` (full suite takes ~60s+; CI gates on this).
- Validators / "lint": `python3 -m tools.uppercut_validate.cli all` (must print `RESULT: OK`).
- These two commands are exactly what CI runs and what must be clean before any push.

### Running the reference simulator

- Round-robin: `python3 -m tools.uppercut_sim.batch [--seeds N] [--rounds N] [--json PATH]`
- Invoke modules from the repository root (`pytest.ini` sets `pythonpath = .`).

### Non-obvious notes

- The reference simulator is a **balance instrument, not the authoritative engine**
  (Decision 0002 / Rule 18). Unreal is authoritative; Python output is reference-only.
- Bouts are **deterministic**. If you change canon in `data/`, expect hash tests to shift.
- `STATUS.md` is generated by `python3 -m tools.gen_status` — never hand-edit it.
- Contribution tagging is required — see `CONTRIBUTION_TAGGING.md`.
